# Measured Evaluation

These results describe the checked-in synthetic arithmetic workflow, not
real-world AI-agent failures. Reproduce them with `python scripts/check.py`.

## Original Training / Test Split

Seed 42 generates 500 runs across 100 scenarios. Related fault variants share a
scenario group. Default training uses 75 scenarios, excludes `answer_mismatch`,
and contains 300 runs. Testing uses the other 25 scenarios: 100 seen-family or
healthy runs plus 25 held-out answer-composition faults. The 75 excluded
answer-composition variants from training scenarios are not used in either set.

| Test slice | Failed | Healthy | Top-1 | Top-3 | Healthy false alarms |
|---|---:|---:|---:|---:|---:|
| Seen fault families + normal | 75 | 25 | 100% | 100% | 0 / 25 |
| Held-out answer composition | 25 | 0 | 100% | 100% | Not applicable |

These are the original `metrics.json` values. The held-out family shares the
existing local-mismatch feature and fixed topology; this is not a new workflow.

## Fresh-Seed Comparator Benchmark

Seeds 101, 202, 303 generate 1,500 additional runs without model retraining:
1,200 failed and 300 healthy. Reports include per-family denominators, fresh-data
fingerprints, Python/sklearn versions, and the exact model-file SHA-256.

| Ranker | Top-1 localization | Mean reciprocal rank | Healthy false alarms |
|---|---:|---:|---:|
| Learned step ranker | 1,200 / 1,200 | 1.0 | 0 / 300 |
| Last error | 0 / 1,200 | 0.0 | 0 / 300 |
| First local evidence | 1,200 / 1,200 | 1.0 | 0 / 300 |

The naive last-error baseline points to the final validator, which is a symptom.
The stronger rule baseline selects the earliest explicit error or consistency
mismatch and uses the same observable checks as the learned model.

**The model does not outperform the rule baseline on this dataset.** Do not
present only the weak comparator as evidence that ML is necessary. Fixed topology
and domain-specific features make this benchmark easy. Fresh seeds show stability
within the generator, not generalization to independently captured agent logs.

Failure-detection precision/recall/F1 are separate from step localization. A rule
can detect every failed run and still select the wrong root cause. Empty metric
denominators are reported as null, not zero or fabricated measurements.

## Executed Replay Benchmark

20 isolated API executions cover four faults x five numeric pairs: zero, mixed
signs, two negative values, cancelling boundaries, and positive boundaries.

- Diagnosis selects the expected step in 20 / 20 cases.
- Fixture-provided correct outputs produce success in 20 / 20 cases.
- Deliberately incorrect corrections leave failure in 20 / 20 cases.
- Original records remain identical in 20 / 20 cases.
- Prefix reuse and suffix execution match the checkpoint in every tested case.

Corrections are fixture-provided known outputs, **not generated by the model**.
This measures executor/replay semantics, not autonomous repair capability.
Tests use temporary local stores and do not alter the live demo history.

## Separate Document Regression Benchmark

`python scripts/document_benchmark.py` runs three fictional source packs with
one healthy run and four injected faults each. The twelve failed cases cover
missing retrieval, archived source selection, unsupported answer, and incorrect
citation. Rule diagnosis localizes 12 / 12; fixture corrections succeed in
12 / 12; intentionally wrong corrections remain failed in 12 / 12. All three
healthy cases succeed. The report includes per-case executed and reused steps,
workflow version, and the SHA-256 of the exact fictional catalog.

These are deterministic controlled regression results. There is no trained
document model, semantic-answer evaluator, or independent real-document test set.
Do not merge these counts into arithmetic ML metrics or call them autonomous repair.

## Remaining Cross-Workflow Gaps

Independent real traces, new workflow topologies, semantic retrieval failures,
multiple simultaneous faults, noisy observations, calibrated scores, and
model-generated alternative actions have not been evaluated. Public API step
precision/recall/F1 fields remain null; the separate report's detection F1 is a
different metric and is not substituted into those fields.
